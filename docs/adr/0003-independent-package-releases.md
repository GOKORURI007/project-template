# 各语言包独立发布

不同语言子项目可能有不同的发布节奏，因此各包独立管理版本，根目录的 `turbo release` 通过 TUI 选择一个或多个发布对象。内置流程管理版本更新、发布提交、tag 及可选的多 remote 推送，渠道发布通过扩展入口配置。相比全仓库统一版本，这个选择避免无关子项目被迫一起升版，同时要求后续发布设计明确包身份、tag 命名和包间依赖的一致性。

内置自动化限于版本元信息、相应 tag 和发布流程。语言适配器校验其原生规则；需要源码迁移、继承版本冲突或依赖不兼容时，明确提示使用者处理，不自动改造源码或连带升级其他包。

发布要求干净工作区。多个 remote 部分推送失败时，保留已生成的版本提交和 tag，展示每个目标的结果，并支持只重试失败目标，不再次升版或重建 tag。

修改版本之前，先执行所有选中包已经配置的 `format:check`、`lint`、`typecheck`、`test`、`build`；全部成功后才修改版本、创建发布提交和 tag。检查阶段不自动修复源码。
