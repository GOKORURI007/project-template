# 统一任务约定

本文件记录已确认的模板任务行为；各子项目的实际业务逻辑由模板使用者配置。

## 语言工具默认值

| 语言 | 格式化与静态检查 |
| --- | --- |
| Node | Prettier、ESLint |
| Python | Ruff、ty |
| Rust | 官方格式化与检查命令 |
| Go | 官方格式化与检查命令 |

## 检查与修复

- `format`：执行格式化。
- `format:check`：只检查格式。
- `lint`：只检查代码问题。
- `lint:fix`：显式自动修复；语言工具不支持修复时，输出普通 info 提示并成功退出，明确没有执行修复。
- `typecheck`：类型或编译检查。
- `test`、`build`：调用各语言原生命令。

## 运行任务

- `dev`：开发运行或监听。
- `start`：正常运行项目。
- `deploy`：执行该包自行配置的部署步骤；模板不绑定部署平台。

全仓库运行时，跳过未提供对应任务的包并给出提示；明确选择单包运行时，缺少任务应报错。

## 工具缺失

`init` 只展示环境适配状态与具体缺失项，不因某种语言不可用而安装工具。

实际执行的任务需要某种语言工具而工具缺失时，该任务明确失败；这条规则与“包没有提供对应任务”的跳过规则不同。其他语言包仍可以单独运行。

## 管理入口

- `turbo init`：交互配置项目元信息和包管理器，检查环境。
- `turbo release`：交互选择发布包、版本和推送目标。
- `turbo manager:update`：显式检查并更新上游管理包目录。
- submodule/subtree：由管理包集中提供 TUI 及相应 Turbo 任务；具体命令命名在实现中保持一致。

初始化、发布与外部源码管理使用共享管理包的 TUI；开发运行中的任务日志使用 Turbo 的任务界面。

## 模板初始内容

模板包含始终保留的共享管理包，以及 Node、Python、Rust、Go 各一个最小示例包。语言示例只演示任务接入，使用者可以删除；模板不预设使用者的业务结构。

## 参考仓库

`python-project-template/` 与 `zotero-addon-template/` 用于提炼约定和交互行为，最终模板无需保留这两个完整仓库。
