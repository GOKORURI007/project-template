# 09: 推送多 remote 发布并恢复失败目标

**What to build:** 维护者在 release TUI 中选择一个或多个 remote，查看各目标结果，并在部分失败后仅重试失败目标；也能接入自己的发布渠道扩展。

**Blocked by:** 04: 交互式独立发布 Node 包到本地

**Status:** resolved

**Spec coverage:** User Stories 40–44, 51, 57, 64；遵守已确认的领域术语、任务约定及相关 ADR。

- [x] 保留仅本地发布能力，TUI 可选择多个推送目标并展示每个目标成功或失败。
- [x] 部分推送失败后保留版本提交与 tag，能够仅重试失败目标，不再次升版、不重建已有 tag、不重复推送已完成目标。
- [x] 正常发布和重试都不隐含推送外部源码上游。
- [x] 提供位于管理包源码之外的发布渠道扩展入口，本地配置优先；不默认绑定 GitHub Release 或某个 registry。
- [x] 通过多个本地 remote 制造部分失败，验证恢复前后的提交、tag 和目标结果；通过可观察的本地扩展验证渠道接入。
