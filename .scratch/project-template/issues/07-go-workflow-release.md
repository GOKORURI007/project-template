# 07: 打通 Go 包检查与独立发布

**What to build:** 使用者可以在统一工作区运行最小 Go 包的官方任务，并按 Go 子目录模块与主版本规则，通过共享 release TUI 建立独立发布记录。

**Blocked by:** 04: 交互式独立发布 Node 包到本地

**Status:** resolved

**Spec coverage:** User Stories 2–3, 22–26, 31–32, 34–35, 37–39, 45；遵守已确认的领域术语、任务约定及相关 ADR。

- [x] 提供可独立删除的最小 Go 示例，统一任务使用官方格式化、vet、编译、测试和构建命令。
- [x] 格式检查发现不合规内容时返回失败；不支持的自动修复输出普通 info 并成功退出。
- [x] 发布版本来自符合 Go 模块规则的记录与 tag，不把其他语言的版本文件规则强加给 Go。
- [x] 子目录 tag 与主版本路径规则得到校验；需要修改模块路径或源码 import 时明确提示，不自动迁移。
- [x] 混合包发布仍遵循全部检查先通过再改版本的原则，缺工具不安装且明确失败。
- [x] 在本地模块与 Git 夹具中，通过公开命令验证任务、tag、主版本约束和失败时无发布变更。
