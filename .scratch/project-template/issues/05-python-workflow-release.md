# 05: 打通 Python 包检查与独立发布

**What to build:** 使用者可以把最小 Python 包加入同一工作区，用统一命令执行 uv／Ruff／ty 工作流，并通过共享 release TUI 按 Python 原生版本规则发布到本地。

**Blocked by:** 04: 交互式独立发布 Node 包到本地

**Status:** resolved

**Spec coverage:** User Stories 2–3, 20, 23–26, 31–32, 34–35, 37–39, 45；遵守已确认的领域术语、任务约定及相关 ADR。

- [x] 提供可独立删除的最小 Python 示例，通过 uv 执行 Ruff 格式与 lint、ty 类型检查及原生测试和构建流程。
- [x] 检查与修复的文件影响及退出码符合统一任务约定；缺工具明确失败且不自动安装。
- [x] 共享发布入口识别 Python 版本元信息，校验 Python 原生版本及预发布表示并生成相应发布记录。
- [x] 在 Node 与 Python 混合选择下，任何已配置检查失败都不会提前修改任一选中包版本。
- [x] 不自动改造源码、传播依赖升级或发布到固定 registry。
- [x] 通过同一公开命令边界验证任务、缺工具和本地发布；原生命令冒烟在工具已显式准备的环境中运行。


## Comments

使用现有 Python 3.13 显式准备示例依赖后，Ruff、ty、pytest 和 wheel/sdist 真实命令通过。公开入口验证了 PEP 440 预发布、UV 项目锁版本、缺环境不安装、原生依赖冲突，以及混合发布失败不改版本；完整集成套件 27 项通过。
