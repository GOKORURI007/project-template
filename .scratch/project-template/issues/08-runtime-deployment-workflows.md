# 08: 协同运行开发任务与自定义部署

**What to build:** 使用者通过统一 dev、start、deploy 入口运行选中的包，利用 Turbo 表达准备任务和协同运行关系，并执行自己的部署步骤。

**Blocked by:** 01: 运行首个 Node 工作流

**Status:** resolved

**Spec coverage:** User Stories 6, 27–32, 62, 64；遵守已确认的领域术语、任务约定及相关 ADR。

- [x] dev 用于开发运行或监听，start 用于正常运行，deploy 调用包自行配置的部署步骤，不绑定部署平台。
- [x] 可演示多个包的准备依赖与协同运行，长期任务采用 Turbo 支持的运行关系，日志使用 Turbo 任务界面。
- [x] 终端输入、任务失败和退出信号按公开命令预期传播；不引入业务健康检查或端口分配器。
- [x] 缺任务的全仓库跳过／显式包失败、缺工具的明确失败规则继续成立。
- [x] 部署等副作用命令不会被缓存结果替代，本地配置可以提供真实可观察的部署扩展。
- [x] 通过临时多包工作区的公开入口验证调度、输入输出、退出结果和自定义部署行为，并附用户说明。


## Comments

验证：50 项公开命令集成测试全部通过，其中 runtime 的 9 项覆盖四种语言运行、自定义部署、准备依赖、真实终端输入和停止后所属进程树退出。ESLint 与格式规范同步整理。
