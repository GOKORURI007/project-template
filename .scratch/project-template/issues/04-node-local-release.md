# 04: 交互式独立发布 Node 包到本地

**What to build:** 维护者通过 turbo release 选择一个或多个 Node 包及各自版本，全部发布前检查通过后生成本地发布提交与 tag；任一目标失败时版本不被提前修改。

**Blocked by:** 02: 交互式初始化项目并诊断环境

**Status:** resolved

**Spec coverage:** User Stories 5, 33–40, 45, 51, 64；遵守已确认的领域术语、任务约定及相关 ADR。

- [x] TUI 支持选包和独立目标版本，管理包默认不参与业务发布，也允许只生成本地发布记录。
- [x] 要求干净工作区，并在修改任何目标版本前完成全部选中包已配置的 format:check、lint、typecheck、test、build。
- [x] 任一检查失败时全部选中版本与发布记录不变；检查阶段不自动修复源码。
- [x] 成功时只按选中包更新版本并创建可追踪的发布记录，未选中包不被连带升级。
- [x] 版本和依赖不兼容时给出明确结果，不自动迁移源码或修改其他包依赖。
- [x] 在临时多包 Git 工作区通过公开命令验证成功、本地多包独立版本、脏工作区拒绝及检查失败不改版本。
